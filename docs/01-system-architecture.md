# 1. System Architecture

## Purpose

The Communication Logbook records communications received or issued by the office and maintains a movement trail showing where each communication was transmitted, forwarded, or received.

## Tables

### Communication

The parent/master table. It represents one registered communication.

Core fields include:

- Communication ID — AppSheet technical key.
- Document No. — human-readable registry number generated by automation.
- Document Type — Request, Reply, Memorandum, Clarification, Notice, Letter, Endorsement, Invitation, Reference Material, or Other.
- Subject — description/title of the communication.
- Date of Document — date shown on the document.
- Communication Status — current status of the communication.
- Remarks — notes required for the logbook/ISO context.
- Attachment — associated document file.
- Related Communication Movements — virtual child relationship.

### Communication Movement

The child table. It records an individual movement or receipt event.

Core fields:

- Movement ID — unique key, generated with `UNIQUEID()`.
- Communication ID — Ref to Communication.
- Communication Type.
- From.
- To.
- Date Received.
- Received By.
- Signature.
- Movement Status.
- Remarks.

`Communication ID` is a Ref to the Communication table and `IsPartOf` is ON.

### Registry Counter

A small control table used to maintain the global registration sequence.

Fields:

- Counter ID — key.
- Current Number — global sequence number.

The sequence is global; it is not reset by year, month, or document type.

## Parent-child relationship

```text
Communication
    |
    | Communication ID
    | 1
    |
    | *
    v
Communication Movement
```

The Communication table contains a virtual column named `Related Communication Movements`.

Its element type is Ref and its referenced table is Communication Movement. The relationship currently uses:

```appsheet
SELECT(
  Communication Movement[Movement ID],
  [Communication ID] = [_THISROW].[Communication ID]
)
```

This explicitly returns Movement records whose Communication ID matches the current Communication.

## Business workflow

```text
Communication is registered
          |
          v
Communication record created
          |
          v
Document No. generated
          |
          v
Communication Detail
          |
          v
Movement may be recorded when the document is actually transmitted/received
          |
          v
Movement Trail grows over time
```

Registration and movement are deliberately separate. A document can exist in the registry without yet having a movement record.
